Current behavior · 12 Nov 2026

Degraded sources do not jump the line.

Four selected sources hold four browser tabs and run independently. A degraded source is not promoted. However, if it is already selected, it keeps its tab until the control plane changes the selection.

Visual overview

The observed selection is based on the live scrape configuration: five sources are enabled, while the four-tab cap admits the first four in configured priority order.

What “degraded” changes

Degraded source that is waiting

It stays waiting. It does not skip ahead of any selected source and does not consume a browser tab.

Degraded source already in a tab

It keeps that tab today. The current scheduler reports the warning but does not automatically replace the source with the next waiting one.

So: no surprise promotion, but also no automatic failover.
If you want to avoid wasting a selected tab after a real degradation, that is a separate health-aware replacement policy—not the behavior currently deployed.

Next step

  1. Keep this policy if stable, predictable source selection is more important than automatically chasing temporary warnings.
  2. Add health-aware replacement only if you want a degraded selected source to surrender its tab after a defined failure window.
